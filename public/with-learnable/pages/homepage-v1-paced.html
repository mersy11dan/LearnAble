Downloadable file

Insert a file hosted at a public https:// URL as a clickable download link. The icon and label are auto-detected from the file extension. Use the tool in the editor toolbar to generate it. 

::file src: https://example.com/handout.pdf ::

Auto-detected types: image (.jpg, .jpeg, .png, .gif, .webp, .svg, .bmp, .ico), video (.mp4, .mov, .webm, .avi, .mkv, .m4v), pdf, notebook (.ipynb), python (.py), js (.js, .jsx, .mjs, .cjs), c (.c, .h), text (.txt, .md, .csv, .log). Unrecognized extensions render with a generic file icon.

Rive Animations

The recommended way to embed a Rive animation is the Library Files tool () in the editor toolbar: pick a .riv asset, choose its artboard and data bindings, and insert it. This produces a library-anchored ::asset ID ... :: tag whose overrides are independent on each page — double-click an inserted asset to reopen the configurator. The raw ::rive data: form below is a low-level escape hatch.

Per-page overrides. The same library asset can render a different artboard, state machine or data bindings on each page. The overrides are configured in the Library Files tool and stored on the tag as a Base64 data: payload (::asset 42 data:<base64-json> ::) — you do not construct this by hand; double-click an inserted asset to reopen the configurator. The src, dimensions, brand and version still resolve from the library file, so the asset stays anchored. 

::rive data: <base64-encoded-JSON> ::

JSON shape:

{
  "src": "https://example.com/animation.riv",
  "width": 1920,
  "height": 540,
  "stateMachine": "State Machine 1",
  "artboard": "MasterBanner",
  "viewModelName": "mbViewModel",
  "viewModelInstanceName": "Instance",
  "bindings": {
    "bannerTitle": "Introduction to the Learning Content",
    "courseSelect": "artboard:SAMPLE_ARTBOARD"
  }
}

Fields:

  • src — URL to the hosted Rive file (.riv) — required
  • width, height — canvas size in pixels (defaults: 400×225)
  • stateMachine — name of the state machine to play
  • artboard — name of the artboard to render (uses default if omitted)
  • viewModelName, viewModelInstanceName — data binding View Model and instance names
  • bindings — object of { propertyName: value } pairs. Type (string, number, boolean, color, enum) is auto-detected. Use "artboard:<name>" as the value to bind an artboard property (e.g., to swap branded variants).

Dynamic values. Binding values may embed {{key}} placeholders, replaced per learner at render time (e.g. "Hello {{learner.first_name}}"). Available keys: learner.first_name, learner.last_name, learner.full_name, learner.email, course, brand, page_name, locale.

Worked example. The JSON {"src":"https://example.com/animation.riv","stateMachine":"State Machine 1"} becomes:

GitHub Content

GitHub content embeds pull a file from a repository's default branch at render time and display it inline. Use the GitHub insert tool in the editor toolbar to fill in the fields and validate the paths — you do not need to construct this by hand. 

::github-content data: <base64-encoded-JSON> ::

JSON shape:

{
  "org": "<org>",
  "repo": "<repo>",
  "path": "<path/to/file.md>",
  "files": ["<path/to/file1.py>", "<path/to/file2.py>"]
}

Fields:

  • org — GitHub organization or user — required
  • repo — repository name — required
  • path — path to the main content file, relative to the repository root — required
  • files — array of supporting file paths, rendered as download links above the main content. Each path is relative to the repository root (same format as path).

Markdown files (.md, .markdown) are rendered inline; other UTF-8 text files are shown in a code block, while non-UTF-8/binary files show a warning instead. Fetched content is cached for 1 hour.

Chidi InlineChat

Chidi embeds use a single data: attribute holding a Base64-encoded JSON config. Use the Chidi insert tool () in the editor toolbar to generate it; double-click an existing tag to edit its config in place — you do not need to construct this by hand. 

::chidi data: <base64-encoded-JSON> ::

JSON shape:

{
  "activityType": "tutor",
  "apiUrl": "https://example.com",
  "cssUrl": "https://example.com/inline/llm-tutor-inline.css",
  "greeting": "Hello! I'm here to help.",
  "jsUrl": "https://example.com/inline/llm-tutor-inline.js",
  "starters": ["I'm ready", "Check my code"],
  "systemPrompt": "You are a helpful tutor..."
}

Fields:

  • jsUrl, cssUrl, apiUrl — URLs for the InlineChat assets and API — required
  • greeting — initial greeting displayed to the student — required
  • starters — array of suggested starter prompts (optional)
  • systemPrompt — system prompt for the AI tutor — required
  • activityType — one of tutor, reflection, guide, content_clarity
